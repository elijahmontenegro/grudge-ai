== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* System Tray Application

The service is the application binary. It runs as a system tray process and is the single backend for everything:

- **RRC proxy** -- Accepts standard LLM API requests from any client. Calls the RRC engine to select prerequisites, assembles the payload, forwards to the actual LLM, parses the response stream, and feeds reasoning content back to the RRC engine for warm carry-forward. Third-party clients point here and get RRC transparently.
- **Agent orchestration** -- Runs the agent loop: planning, tool execution, self-correction. Uses the core library's tool system and LLM interface.
- **Conversation storage** -- Owns persistent, complete, unmodified conversation history. Satisfies the lossless corpus property on behalf of the web UI.
- **{api-protocol} API** -- The contract between the service and the web UI. Covers everything: agent orchestration, conversation management, RRC introspection, service configuration.
- **Static asset serving** -- Serves the web UI on localhost. The user opens their browser.
- **Service management UI** -- Lightweight tray-accessible interface for status, config, health. Independent of the full agentic web UI.

=== Scope

==== In Scope

- System tray integration (Windows primary, cross-platform later)
- Service lifecycle: start, stop, health check, configuration
- RRC proxy: HTTP endpoint accepting standard LLM API requests, transparent forwarding via RRC engine
- Response stream parsing: SSE/chunked passthrough with concurrent extraction of reasoning content for warm carry-forward
- Agent orchestration: agent loop, planning, tool execution, self-correction
- Conversation storage: persistent, complete, unmodified history (lossless corpus guarantee)
- {api-protocol} API: full schema and resolvers (orchestration, conversations, RRC introspection, config)
- Static asset serving: web UI files on localhost
- Service management UI: lightweight status/config accessible from tray
- Provider routing: configuration for which upstream LLM to forward to

==== Out of Scope

- The RRC algorithm itself (belongs to `spec/rrc`; the service calls it)
- LLM/embedder interface or adapter definitions (belongs to `spec/core`)
- Proto truth type definitions (belongs to `spec/core`)
- Agentic UI, RRC introspection views, UX patterns (belongs to `spec/web`)
- Cloud deployment or multi-tenancy
