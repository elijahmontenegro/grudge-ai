The RRC engine is a Go library implementing the {rrc-full} algorithm. It operates on data structures (prerequisite DAG, QUD graph, score cache, embedding cache) that the service owns and persists. The engine reads and writes these structures; the service is responsible for their storage and lifecycle.

The service imports this library. The engine does not know it runs inside a proxy.

== Implementation

=== Prerequisite Detection

Two mechanisms produce edges in the prerequisite DAG. Both run on message arrival, not at query time.

==== Cross-Encoder Pairwise Dependency Classification

A single cross-encoder classifies the dependency relationship between two messages. One model, one forward pass per pair.

When message M_n arrives, the cross-encoder evaluates every (M_i, M_n) pair for i < n. Each pair produces a dependency score. Pairs scoring above threshold become edges in the prerequisite DAG.

The cross-encoder captures multiple facets of dependency implicitly through a single classification:

- **Entity reference dependency** (coreference) -- "that function" in M_n refers to something defined in M_i
- **Discourse dependency** (elaboration, cause, instantiation) -- M_n elaborates on, is caused by, or instantiates M_i
- **Logical prerequisite** -- M_n cannot be understood without M_i

These are not separate operations. They are theoretical lenses from NLP research (coreference resolution, PDTB discourse relations, prerequisite chain learning) that explain WHY the cross-encoder's entailment signal captures dependency. The model does not know these categories exist. It takes two texts in, classifies their logical relationship, outputs class probabilities.

Off-the-shelf NLI (Natural Language Inference) cross-encoders classify: entailment, contradiction, neutral. Entailment approximates dependency. Contradiction approximates non-dependency. Neutral approximates unrelated. No fine-tuning required.

Research basis: NLI cross-encoders (DeBERTa-v3 family), PDTB discourse relation framework, coreference resolution (CODI-CRAC), prerequisite chain learning (Liang et al., Gordon et al.).

==== QUD (Questions Under Discussion) Graph

The QUD graph captures what the cross-encoder cannot: long-range structural dependency through the conversation's question-answer flow.

Every message addresses an implicit question and may raise new ones. If message M_47 raises a question and message M_312 answers it, M_47 is a prerequisite of M_312 -- even if they share no surface similarity and the cross-encoder would not score them highly as a pair.

- Uses an LLM (via core LLM interface) for QUD analysis. The model is provider-agnostic.
- Each message is analyzed for: which existing QUDs it addresses (partially or fully), and what new QUDs it raises
- The QUD graph is maintained incrementally: one LLM call per new message
- The LLM receives: current QUD graph state (~500-2000 tokens) + recent message window + the new message. It never needs the full conversation. The graph IS the conversation's structural memory.

QUD graph state:

- QUDs: question text, established-by message, parent QUD, status (open/partially-addressed/resolved), addressed-by messages
- Active stack: open QUDs ordered by recency
- Resolved set: closed QUDs retained for graph completeness
- Derived edges: source message -> target message, via QUD, with type (establishes->addresses, raises->resolves)

Research basis: Roberts (1996) QUD stack theory, Riester (2019) QUD tree construction, Benz & Jasinskaja (2017) mapping discourse relations to QUD. No automatic QUD system exists in the literature -- this is novel.

=== Data Structures

The engine operates on four data structures. The service owns their persistence; the engine reads and writes them.

==== Embedding Cache

One vector per message, computed on arrival via core embedder interface. Vectors are fixed-size, pre-computed, and never become stale (messages are immutable in a conversation).

==== Score Cache

Cross-encoder pairwise dependency scores. When message M_n arrives, the engine scores every (M_i, M_n) pair and writes results to the cache. At query time, scores are already available -- no cross-encoder inference needed.

Conversations are append-only. Message content never changes. Cached scores do not become stale.

==== QUD Graph

Structural compression of conversation flow. Maintained incrementally by an LLM call per new message. Compact: ~50KB for a 1000-message conversation.

==== Prerequisite DAG

The central data structure tying both detection mechanisms together.

**Structure:** Dual adjacency list -- two indexes over the same edge set:

- **Backward:** message -> its prerequisites (messages it depends on). The primary traversal direction for RRC.
- **Forward:** message -> its dependents (messages that depend on it). Used for impact analysis and introspection.

Edges carry: source, target, score, detection source (cross-encoder, QUD, or both), timestamp.

Temporal ordering guarantees acyclicity: edges only point from earlier messages to later messages. No cycle detection needed.

**Persistence:** Append-only edge log. Each new edge is appended as a record. On startup, replay the log to rebuild the in-memory graph.

=== Selection Scoring

==== Score Fusion

Each prerequisite edge carries scores from the signals that produced it:

- **Cross-encoder dependency score** -- Pairwise classification confidence
- **QUD edge weight** -- Structural dependency derived from QUD graph (established->addressed, raised->resolved)
- **Temporal proximity** -- Decay function over message distance

Final edge score is a weighted combination. Signal weights are a tuning parameter.

==== Bounded Selective Assembly

Zero-return is valid. If no message scores above threshold, the prompt is novel and the model receives it without augmentation.

=== Payload Assembly

==== Subgraph Extraction

Best-first backward traversal from the prompt through the prerequisite DAG:

1. Seed priority queue with direct prerequisites of the prompt, ordered by edge score
2. Pop highest-score message, add to selection, subtract its tokens from budget
3. Push its prerequisites with multiplicatively decayed scores (effective_score = edge_score * parent_score)
4. Repeat until token budget exhausted or queue empty
5. Depth limit as safety bound

==== Transitive Reduction

Computed on demand over the selected subgraph, not maintained globally. The selected subgraph is small (typically 5-30 messages); reduction is trivial.

Removes redundant edges: if A->B->C and A->C, remove A->C from the selection. The minimal chain is what the model needs.

==== Native Format Restoration

Selected messages are ordered chronologically and placed in the model's input as ordinary conversation entries. No template, no label. Structurally indistinguishable from session history.

=== Warm Carry-Forward

The service parses the LLM's response stream and feeds extracted content back to the engine. Two forms:

==== QUD Enrichment

The LLM's response is analyzed for QUDs it addresses and raises. This feeds back into the QUD graph, improving future prerequisite detection. Every RRC request is also a QUD analysis opportunity.

Enrichment is additive only -- it adds edges and updates QUD status toward resolution. It never removes edges or re-opens resolved QUDs. This prevents oscillation.

==== Reasoning Cache

Reasoning content extracted from the LLM's response (chain-of-thought, decision rationale, identified relationships) is cached and available to enrich the selection prompt on subsequent requests.
