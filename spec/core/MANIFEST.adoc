== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* Provider-Agnostic Abstraction Library

The core library is the foundational Go module. It defines the proto truth types, abstraction interfaces, and provider/embedder/classifier adapters that all other modules consume. It has no opinion on RRC, orchestration, UI, or deployment.

=== Stack

*Language:* {lang}

*Code Generation:* {codegen}

*Truth Types:* Protocol Buffers (`.proto` files in `proto/spidey/v1/` are the canonical source; Go types generate to `gen/go/spidey/v1/`)

*Dependencies:* Standard library plus: `google.golang.org/protobuf`, `modernc.org/sqlite` (for adapters that need local state). No framework dependencies.

=== Scope

==== In Scope

- Proto truth types: Message, LLMMessage, ContentBlock (Text, Thinking, ToolCall, ToolResult, Image), Thread, Role, SelectionScope, Edge, QUD, QUDGraph, SelectionResult, CarryForwardInput, ClassifyRequest/Response, CompletionRequest/Response, StreamChunk, Usage
- LLM interface: completion, streaming completion
- Embedder interface: single embed, batch embed
- Classifier interface: pairwise text classification (cross-encoder pattern -- takes two texts, returns class probabilities)
- Provider interface: lifecycle, capability discovery, configuration
- Provider adapters: Ollama, Anthropic, OpenAI, Google AI, vLLM, any OpenAI-compatible endpoint
- Embedder adapters: TEI, OpenAI embeddings
- Classifier adapters: TEI rerank/predict endpoint, custom inference endpoints
- Code generation pipeline: proto -> Go types via buf

==== Out of Scope

- RRC engine or algorithm (belongs to `spec/rrc`)
- Agent orchestration, agent loop, planning (belongs to `spec/service`)
- HTTP server, proxy, or service concerns (belongs to `spec/service`)
- UI, GraphQL schema, or presentation (belongs to `spec/web`)
- Conversation storage or persistence (belongs to `spec/service`)

== Implementation

=== Proto Truth Types

Defined in `proto/spidey/v1/`. Generated Go types in `gen/go/spidey/v1/`. Four files:

- **thread.proto** -- Message, Role, ContentBlock (TextContent, ThinkingContent, ToolCallContent, ToolResultContent, ImageContent), Thread, SelectionScope
- **rrc.proto** -- Edge, EdgeSource, QUD, QUDStatus, QUDGraph, SelectedMessage, ExcludedMessage, ExclusionReason, SelectionResult
- **classifier.proto** -- ClassifyRequest, ClassifyResponse, ClassLabel, BatchClassifyRequest, BatchClassifyResponse
- **llm.proto** -- LLMMessage, CompletionRequest, CompletionResponse, Usage, StreamChunk

Message is the corpus record (id, role, content blocks, position, thread_id, created_at). LLMMessage is the wire format (role, content blocks only). The service converts between them at the boundary. Thread is the organizational unit -- each thread is its own corpus with its own DAG, QUD graph, and carry-forward trajectory. SelectionScope controls per-prompt scoping (thread-scoped by default, all-threads as opt-in).

CompletionRequest includes `provider_options` (`google.protobuf.Struct`) as an escape hatch for provider-specific parameters the abstraction does not model explicitly.

=== Go Interfaces

Provider-agnostic interfaces. The RRC engine and service consume these without knowing the backend. The service configures two LLM roles: the **main model** (user's model for reasoning, tool use, responses) and the **small fast model** (internal utility for QUD extraction, annotations, autocomplete, tool rationale — needs to be near-free per call). Both use the same Completer interface with different provider/model configurations.

==== LLM

[source,go]
----
type Completer interface {
    Complete(ctx context.Context, req *pb.CompletionRequest) (*pb.CompletionResponse, error)
    Stream(ctx context.Context, req *pb.CompletionRequest) (<-chan *pb.StreamChunk, error)
}
----

==== Embedder

[source,go]
----
type Embedder interface {
    Embed(ctx context.Context, text string) ([]float32, error)
    EmbedBatch(ctx context.Context, texts []string) ([][]float32, error)
}
----

==== Classifier

[source,go]
----
type Classifier interface {
    Classify(ctx context.Context, req *pb.ClassifyRequest) (*pb.ClassifyResponse, error)
    ClassifyBatch(ctx context.Context, req *pb.BatchClassifyRequest) (*pb.BatchClassifyResponse, error)
}
----

=== Provider Interface

Every adapter (LLM, embedder, classifier) is created through a provider. The provider handles lifecycle and configuration.

[source,go]
----
type Provider interface {
    ID() string
    Completer(model string) (Completer, error)
    Embedder(model string) (Embedder, error)
    Classifier(model string) (Classifier, error)
    Close() error
}
----

Not every provider supports all three capabilities. `Completer()` on a TEI provider returns an error. `Classifier()` on a pure LLM provider returns an error. The caller checks.

=== Provider Adapters

Each adapter implements `Provider` for a specific backend. Configuration is adapter-specific.

==== Ollama
- Supports: Completer, Embedder
- Endpoint: configurable HTTP base URL
- Models: whatever is pulled locally

==== Anthropic
- Supports: Completer
- Endpoint: Anthropic Messages API
- Auth: API key

==== OpenAI
- Supports: Completer, Embedder
- Endpoint: OpenAI API (or any OpenAI-compatible endpoint -- configurable base URL)
- Auth: API key

==== Google AI
- Supports: Completer, Embedder
- Endpoint: Gemini API
- Auth: API key

==== vLLM
- Supports: Completer
- Endpoint: OpenAI-compatible API (configurable base URL)
- Auth: optional API key

==== TEI
- Supports: Embedder, Classifier
- Endpoint: configurable HTTP base URL
- Embedder uses `/embed`, Classifier uses `/rerank` or `/predict`

=== Code Generation Pipeline

Proto compilation via `buf`. Configuration in `buf.yaml` at the repository root.

Input: `proto/spidey/v1/*.proto`
Output: `gen/go/spidey/v1/*.go`

Downstream: GraphQL schema (in service spec) and TypeScript types (in web spec) generate from these Go types, not directly from proto.
