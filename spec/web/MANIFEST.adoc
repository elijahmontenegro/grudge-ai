== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* RRC-Native Agentic Interface

The web UI is a {ui-framework} application served by the service at `spidey.localhost`. The browser opens automatically when the service launches. It is the agentic interface -- not a chat clone.

Three things make this different from every other agentic UI:

1. **Citations.** Every message carries its RRC selection metadata -- which prior messages were selected as prerequisites, their scores, which thread they came from, whether the cross-encoder or QUD found them. The user sees what informed every response.
2. **Threads, not conversations.** Each thread is its own corpus with its own DAG, QUD graph, and carry-forward trajectory. Selection is thread-scoped by default, widened to all threads per-prompt. Each thread develops its own identity through accumulated carry-forward.
3. **Agentic surface.** Tool visualization, agent state, execution traces. The user sees what the agent is doing, why, and can intervene.

=== Scope

==== In Scope

- Thread model: create, name, switch, delete threads. No "conversations" -- threads are the organizational unit.
- Per-prompt scope control: thread-scoped selection by default, toggle to all-threads for a specific prompt
- Citations per message: every message that triggered an RRC selection event carries citation metadata (selected prerequisites, scores, thread origin, cross-thread indicator)
- RRC introspection: drill into citations to see full selection detail, QUD graph state, carry-forward history
- Agentic interface: tool visualization, agent state, execution traces
- Message display: rich content (text, code, tool results, images) -- not a plain chat list
- Home page: landing view when opening Spidey
- Autonomous mode controls: duration picker, play/pause/stop, progress display, thread state in sidebar
- {api-client} integration: queries, mutations, subscriptions against the service {api-protocol} API
- Code generation: {api-protocol} schema -> TypeScript client types via {codegen}
- Build output: static assets (HTML/JS/CSS) served by the service

==== Out of Scope

- Backend logic (belongs to `spec/service`)
- Agent orchestration or tool execution (belongs to `spec/service`; this is the visualization surface)
- Thread storage (belongs to `spec/service`; the UI reads/writes via {api-protocol})
- RRC engine or algorithm (belongs to `spec/rrc`; the UI displays results)
- Standalone server or hosting (served by the service)
- Mobile layout

== User Stories

=== Thread Management

- User opens Spidey -> sees thread list with state indicators (idle, running, paused) and warmth (carry-forward count) -> picks a thread or creates one
- User creates a thread -> types a name or starts with a prompt (thread auto-named from first prompt) -> adds one or more working directories
- User adds or removes mounted directories from a thread at any time
- User sees which threads are running/paused/idle from any view via the persistent sidebar

=== Normal Interaction

- User types a prompt -> chooses scope (thread or all-threads) -> sends
- Agent works -> user sees streaming response, tool executions and thinking blocks expand/collapse inline
- User stops the agent mid-execution -> agent halts, partial work preserved in thread

=== Citations

- User sees citation count on every message that went through an RRC selection event
- User expands citations inline -> sees listed prerequisites with score, source (cross-encoder / QUD / both), thread origin
- User clicks a cited message -> navigates to it (scrolls within thread or jumps to other thread)
- User sees outbound indicator on messages -> "referenced by N later messages"
- Cross-thread citations are visually distinct from same-thread citations

=== Autonomous Mode

- User switches to autonomous mode -> duration picker appears
- User types initial prompt -> sets duration (5m to 2w) -> hits play
- Agent runs -> user sees progress (round count, elapsed time, current activity)
- User pauses -> input area appears for course correction -> types correction -> resumes
- User stops -> agent halts -> thread shows final state
- Timer expires -> agent stops naturally
- User can navigate to other threads while autonomous agent runs -- progress visible in sidebar

=== Tool Permissions

- Agent requests a write tool (file edit, bash) -> user sees pending tool call with details -> approves or denies
- User configures per-thread permission defaults (allow/ask/deny per tool category)
- Denied tool call -> agent sees denial, adjusts approach

=== Cross-Thread

- User toggles scope to all-threads for a specific prompt -> agent draws from all threads
- User sees cross-thread citations highlighted distinctly in citation expansion
- User navigates from a cross-thread citation to the source thread and back without losing state

=== First Run

- User launches Spidey for the first time -> service starts, tray icon appears, browser opens
- Onboarding: user provides name and preferences (stored once, injected into prompt templates)
- Service probes localhost for Ollama (default port) and TEI (default port)
- Detected -> shows detected providers (LLM, cross-encoder, small fast model), user confirms
- Not detected -> setup form: endpoint URLs, model selection, API key for cloud providers
- All three model roles configured -> home page loads -> ready

=== Errors

- LLM provider unreachable -> error shown in thread, agent pauses, user can retry or reconfigure in settings
- Cross-encoder (TEI) unreachable -> system does not work. RRC is not optional. Error displayed, links to settings, system waits until resolved. No degraded mode, no passthrough.
- Autonomous run fails mid-execution -> agent pauses with error visible, user reviews, retries or stops
- Service restarts while autonomous agent is running -> agent state shows last known state on reconnect

=== Introspection (drill-down from citations)

- User expands a citation -> sees score breakdown (cross-encoder, QUD, temporal proximity)
- User views the QUD graph state at the time of that selection event
- User sees what the model actually received (assembled payload) vs the full thread

== Prerequisites

These are not features. They are conditions the user stories depend on.

=== State Persistence Across Navigation

Thread view state survives navigation -- scroll position, expanded/collapsed sections, input draft. Leave and come back, it's the same. This is session state managed by the service, not the browser. Tab close and reopen restores it.

=== Service Restart Resilience

If the service restarts, all persistent state survives (threads, messages, DAG, scores, QUD graphs in SQLite). Session view state is reconstructable. Running autonomous agents resume or show their last state. The browser reconnects automatically.

=== Concurrent Thread Awareness

Multiple threads can be active simultaneously. Navigating between threads does not affect running agents. The sidebar reflects all thread states in real time regardless of which thread the user is in.

=== Real-Time Updates Across Views

Agent progress updates in the sidebar even when the user is in a different thread. Cross-thread citations appearing in the home activity feed while the user is in a thread. All via {api-protocol} subscriptions.

=== Navigation History

Citation jumps are navigation events. Browser back/forward work naturally. `spidey.localhost/thread/{id}` is a real URL. Back returns to the same scroll position and expanded state.

=== Offline Resilience

If the browser disconnects (network blip, tab backgrounded), the session reconnects and rehydrates from the service. No data loss. The service is the source of truth.

=== Input Draft Persistence

User starts typing, navigates away, comes back -- draft is still there. Per-thread.

== Implementation

=== Layout

Persistent sidebar (always visible): thread list with state indicators (idle, running, paused, with elapsed time for running threads). Main area changes based on context: home feed when no thread selected, thread view when inside a thread.

=== Home Page

Main area when no thread selected. Activity feed: recent cross-thread citations, completed autonomous runs. Quick start: prompt input that creates a new thread and sends in one action. New thread button.

=== Thread Warmth

Count of carry-forward events in a thread -- how many LLM responses have fed back into the thread's QUD graph. A thread with 0 is cold (cross-encoder edges only, no structural understanding). A thread with 200 is warm (rich QUD graph, strong identity). Displayed as a subtle indicator in the sidebar per thread and in the home activity feed.

=== Thread View

Single column message stream, vertical scroll. Tool executions and thinking blocks expand/collapse inline (standard agentic pattern). Citation indicator per message -- expand inline to see RRC selection detail. Streaming tokens arrive in real time via subscription. Rich content: text, code blocks, tool results, images.

=== Citations

Citation indicator per message: count of selected prerequisites. Expand inline to see: message preview, score, source (cross-encoder / QUD / both), thread origin if cross-thread. Cross-thread citations visually distinct. Click a cited message to navigate to it. Outbound indicator: "referenced by N later messages."

=== Introspection

Drill-down from citation expansion. Selection detail: full ranked list, scores, traversal path through DAG. Score breakdown per edge: cross-encoder score, QUD edge weight, temporal proximity. Exclusion rationale: why specific messages were not selected (below threshold, transitive reduction, depth limit). QUD graph view: open/resolved QUDs, which messages establish and address each. Carry-forward view: accumulated reasoning. DAG neighborhood: for a given message, its prerequisites and dependents.

=== Input Area

Two modes driven by user's cognitive state:

**Idle:** Text area, send button, scope toggle (thread / all-threads), mode switch (normal / autonomous).

**Autonomous setup:** When autonomous mode selected, duration picker appears (5m to 2w). Text area stays for the initial prompt. Send becomes play.

**Agent working (normal):** Stop button appears. Text area available for interruption.

**Agent working (autonomous):** Pause + stop. Duration countdown. Progress: round count, elapsed time, current activity.

**Agent paused (autonomous):** Text area returns for course correction. Resume + stop. User types correction, hits resume, correction enters the thread, agent continues.

=== Settings

Minimal. The system should just work. Configuration required on first run:

- Provider endpoint (where is the LLM? Ollama at localhost, Anthropic API, etc.)
- Model selection
- API key (for cloud providers)
- Classifier endpoint (where is the cross-encoder? TEI at localhost, etc.)

Smart detection: if Ollama and TEI are running at default localhost ports, detect and offer them. Reduce first-run friction to confirmation, not configuration.

Per-thread settings: mounted directories (add/remove), sandbox on/off, tool permissions (allow/ask/deny per tool).

Accessible from tray menu ("Settings...") and from within the web UI.

=== UI Architecture
