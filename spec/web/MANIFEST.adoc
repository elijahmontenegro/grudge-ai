== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* RRC-Native Agentic Interface

The web UI is a {ui-framework} application served by the service on localhost. The user opens their browser. It is the agentic interface -- not a chat clone. What a CLI agentic tool would be if it had a full graphical surface.

Two things make this different from every other agentic UI:

1. **RRC introspection.** It sees what RRC selected, what it excluded, the prerequisite scores, and the prompt derivation. No other client has this because RRC is novel. This visibility is the product differentiator.
2. **Agentic surface.** Tool visualization, agent state, execution traces, planning views. The user sees what the agent is doing, why, and can intervene.

=== Scope

==== In Scope

- RRC introspection views: selection visualization, prerequisite scores, prompt derivation, exclusion rationale, carry-forward state
- Agentic interface: tool visualization, agent state, execution traces, planning views
- Conversation interface: message display, input, history navigation (not a chat clone -- the agentic context is primary)
- {api-client} integration: queries, mutations, subscriptions against the service {api-protocol} API
- Code generation: {api-protocol} schema -> TypeScript client types via {codegen}
- UX design: interaction patterns, layout, information architecture, responsiveness
- Build output: static assets (HTML/JS/CSS) served by the service

==== Out of Scope

- Backend logic (belongs to `spec/service`)
- Agent orchestration or tool execution (belongs to `spec/service`; this is the visualization surface)
- Conversation storage (belongs to `spec/service`; the UI reads/writes via {api-protocol})
- RRC engine or algorithm (belongs to `spec/rrc`; the UI displays results)
- Standalone server or hosting (served by the service)
- Mobile layout
