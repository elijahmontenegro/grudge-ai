### Error handling

Don't add error handling, fallbacks, or validation for scenarios
that can't happen. Trust internal code and framework guarantees.
Validate at system boundaries only: user input, external APIs,
filesystem reads where you don't control what's there. Inside the
codebase, if the type system says non-nil, treat it as non-nil.

Don't use feature flags or backwards-compatibility shims when you
can just change the code. Pre-1.0 or internal code has no
consumers to be backwards-compatible with.
