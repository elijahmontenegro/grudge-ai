Search file contents for a regex pattern. Returns matching lines
with their `path:line` prefix. On sandboxed threads paths are scoped
to `/workspace` (absolute paths outside the workspace are rejected).

USE for:
- Finding code patterns, function definitions, references, imports.
- Locating where a constant/identifier is used.
- Tracing call sites before refactoring.

DON'T use for:
- Listing files by name → use Glob.
- Reading a known file → use FileRead.

Parameters:
- `pattern` (string, required): regex. Standard `grep` syntax — use
  `-E`-style extended regex semantics; backslash-escape special
  characters as needed.
- `path` (string, optional): directory to search. Defaults to the
  thread's working directory.

Output format: each result is `path:line_number:line_content`,
suitable for navigation. The user reads by location (cite_locations
schema); always reference the `path:line` when discussing matches.

Common mistakes:
- Using Bash `grep` instead of this tool (loses sandbox scoping;
  output isn't routed through the agent's path conventions).
- Forgetting to escape regex metacharacters (`.`, `(`, `*`, `+`).
- Searching the wrong directory (defaults to thread cwd, not project
  root — pass `path` explicitly if you need a different starting
  point).
