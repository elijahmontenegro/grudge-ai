== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* Provider-Agnostic Abstraction Library

The core library is the foundational Go package. It defines the abstraction interfaces and provider/embedder/scorer adapters. Proto truth types are defined in `proto/spidey/v1/` and generate to `proto/gen/go/spidey/v1/` -- core imports them, it does not own them. Core has no opinion on RRC, orchestration, UI, or deployment.

=== Stack

*Language:* {lang}

*Code Generation:* {codegen}

*Truth Types:* Protocol Buffers (`.proto` files in `proto/spidey/v1/` are the canonical source; Go types generate to `proto/gen/go/spidey/v1/`)

*Proto Syntax:* {proto-syntax}

*Dependencies:* Standard library plus: `google.golang.org/protobuf v1.36.3`. No framework dependencies.

=== Scope

==== In Scope

- Proto truth types: Message, LLMMessage, ContentBlock (Text, Thinking, ToolCall, ToolResult, Image), Thread, Role, SelectionScope, Edge, QUD, QUDGraph, SelectionResult, CarryForwardInput, CompletionRequest/Response, StreamChunk, Usage
- Completer interface: completion, streaming completion
- Embedder interface: dispatched embed (RoleQuery / RoleDocument)
- Scorer interface: query-against-candidates relevance scoring (cross-encoder pattern -- one query, N candidates, returns aligned scores)
- Codec interface: per-adapter proto ↔ wire-format conversion
- Provider role interfaces: CompleterProvider, EmbedderProvider, ScorerProvider (interface-segregated; each adapter implements only the roles it supports)
- Provider adapters: Ollama, Anthropic, OpenAI, Google AI, vLLM, any OpenAI-compatible endpoint
- Embedder adapters: TEI, OpenAI embeddings
- Scorer adapters: TEI `/rerank`, zerank/vLLM `/v1/chat/completions`
- Code generation pipeline: proto -> Go types via buf

==== Out of Scope

- RRC engine or algorithm (belongs to `spec/rrc`)
- Agent orchestration, agent loop, planning (belongs to `spec/service`)
- HTTP server, proxy, or service concerns (belongs to `spec/service`)
- UI, GraphQL schema, or presentation (belongs to `spec/web`)
- Conversation storage or persistence (belongs to `spec/service`)

== Implementation

=== Proto Truth Types

Defined in `proto/spidey/v1/`. Generated Go types in `proto/gen/go/spidey/v1/`. Three files:

- **thread.proto** -- Message, Role, ContentBlock (TextContent, ThinkingContent, ToolCallContent, ToolResultContent, ImageContent), Thread, SelectionScope
- **rrc.proto** -- Edge, EdgeSource, QUD, QUDStatus, QUDGraph, SelectedMessage, ExcludedMessage, ExclusionReason, SelectionResult
- **llm.proto** -- LLMMessage, CompletionRequest, CompletionResponse, Usage, StreamChunk

Scorer is a Go interface only -- (query, []candidates) -> []float64 -- and has no proto wire form. Per-adapter HTTP shapes (TEI's `/rerank`, vLLM's `/v1/chat/completions` with the zerank Yes-token logprob recipe) live in each adapter's package.

Message is the corpus record (id, role, content blocks, position, thread_id, created_at). LLMMessage is the wire format (role, content blocks only). The service converts between them at the boundary. Thread is the organizational unit -- each thread is its own corpus with its own DAG, QUD graph, and carry-forward trajectory. SelectionScope controls per-prompt scoping (thread-scoped by default, all-threads as opt-in).

CompletionRequest includes `provider_options` (`google.protobuf.Struct`) as an escape hatch for provider-specific parameters the abstraction does not model explicitly.

=== Go Interfaces

Provider-agnostic interfaces. The service consumes these without knowing the backend. The RRC engine defines its own consumer interface (Scorer) via Go structural typing -- any core adapter satisfies it.

The service configures two LLM roles: the **main model** (user's model for reasoning, tool use, responses) and the **small fast model** (internal utility for QUD extraction, annotations, autocomplete, tool rationale). Both use the same Completer interface with different provider/model configurations. The small fast model requires sub-second inference latency for autocomplete; QUD extraction tolerates multi-second latency. User selects a model matching these constraints during onboarding. Recommended models for the small fast role: sub-1B extraction-focused (Osmosis-Structure-0.6B, NuExtract-tiny, Qwen3.5-0.8B).

==== Embedder

[source,go]
----
type EmbedRole int

const (
    RoleQuery EmbedRole = iota
    RoleDocument
)

type Embedder interface {
    Embed(ctx context.Context, role EmbedRole, texts []string) ([][]float32, error)

The role dispatch is for asymmetric instruction-tuned embedders (Qwen3-Embedding etc.) that need a query-side Instruct/Query prefix; symmetric models (bge-m3) ignore the role.

==== Scorer

[source,go]
----
type Scorer interface {
    Score(ctx context.Context, query string, candidates []string) ([]float64, error)
}
----

Higher score = more relevant. Output is aligned with input candidate order. Empty candidates returns an empty slice with no backend call.

=== Provider Role Interfaces

Adapters implement only the role interfaces they support. Splitting the god-interface (one method per role) means each adapter's capability surface is observable from its method set, not from a runtime probe. Callers type-assert on the role interface they need.

[source,go]
----
type CompleterProvider interface {
    Completer(model string) (Completer, error)
}

type EmbedderProvider interface {
    Embedder(model string) (Embedder, error)
}

type ScorerProvider interface {
    Scorer(model string) (Scorer, error)
}
----

A backend that exposes multiple roles (TEI: embeddings + reranking) implements multiple role interfaces. A pure-LLM provider implements only `CompleterProvider`. `ErrUnsupported` is returned by the registry lookup boundary when a caller requests a role the registered adapter doesn't satisfy.

=== Provider Adapters

Each adapter implements `Provider` for a specific backend. Configuration is adapter-specific.

==== Ollama
- Supports: Completer, Embedder
- Target API: Ollama HTTP API (as of v0.20.x)
- Endpoint: configurable HTTP base URL
- Models: whatever is pulled locally

==== Anthropic
- Supports: Completer
- Target API: Anthropic Messages API (`anthropic-version: 2023-06-01`)
- Endpoint: configurable base URL (default: `https://api.anthropic.com`)
- Auth: API key (`x-api-key` header)

==== OpenAI
- Supports: Completer, Embedder
- Target API: OpenAI `/v1/` (Chat Completions, Embeddings)
- Endpoint: configurable base URL (default: `https://api.openai.com`; any OpenAI-compatible endpoint)
- Auth: API key (`Authorization: Bearer` header)

==== Google AI
- Supports: Completer, Embedder
- Target API: Gemini API `v1` (stable)
- Endpoint: Gemini API
- Auth: API key

==== vLLM
- Supports: Completer
- Target API: OpenAI-compatible `/v1/` (as of vLLM 0.14.x)
- Endpoint: configurable base URL
- Auth: API key is a string config field. Empty string: adapter sends no `Authorization` header.

==== TEI
- Supports: Embedder, Scorer
- Target API: TEI HTTP endpoints (as of TEI 1.9.x)
- Endpoint: configurable HTTP base URL
- Embedder uses `/embed`, Scorer uses `/rerank`

==== zerank
- Supports: Scorer
- Target API: vLLM-served OpenAI-compatible `/v1/chat/completions`
- Endpoint: configurable HTTP base URL (default: `http://localhost:8000`)
- Production reranker — zeroentropy/zerank-1-small (1.7B Qwen3-based causal LM). Cross-encoder scoring via Yes-token logprob recipe: `sigmoid(logit / 5)`

=== Error Types

Sentinel errors. No retries -- the caller handles all error policy.

[source,go]
----
var (
    ErrUnsupported         = errors.New("capability not supported by provider")
    ErrAuth                = errors.New("authentication failed")
    ErrProviderUnavailable = errors.New("provider endpoint unreachable")
    ErrRateLimited         = errors.New("provider rate limit exceeded")
)
----

A type-assert on the wrong role interface fails — calling `core.NewProvider(...)` and asserting `(core.CompleterProvider)` on an adapter that doesn't expose completions returns `ErrUnsupported` at the assertion. Network failures return `ErrProviderUnavailable`. Invalid or expired API keys return `ErrAuth`. HTTP 429 from any provider returns `ErrRateLimited`.

Batch failure is all-or-nothing: any item fails → entire batch fails. `EmbedBatch` and `ClassifyBatch` do not return partial results.

=== HTTP Client

Internal shared HTTP client (`internal/httpc/client.go`). Used by all adapters.

[source,go]
----
type Client struct {
    http    *http.Client
    authFn  func(req *http.Request) // per-adapter auth (x-api-key, Bearer, etc.)
}

func New(timeout time.Duration, authFn func(*http.Request)) *Client
----

Default timeouts: 30s for non-streaming requests, 120s for streaming. Auth is a callback injected at construction — each adapter provides its own (Anthropic sets `x-api-key`, OpenAI sets `Authorization: Bearer`, Ollama/TEI set nothing).

=== Stream Contract

The adapter closes the channel when the stream ends or the context is cancelled. Channel is unbuffered. All `Completer`, `Embedder`, and `Scorer` implementations must be safe for concurrent use by multiple goroutines.

**`Complete` vs `Stream` method contract:** `Stream()` sets `stream=true` on the wire regardless of the proto field value. `Complete()` sets `stream=false`. The proto `bool stream` field exists for proto-level consumers; Go callers use method selection.

**Mid-stream errors:** `StreamChunk` carries an `optional string error` field. A chunk with `done=true` and `error` set indicates stream failure. Unexpected channel closure (no `done=true` received) is also an error — the caller treats it as a connection drop.

=== Code Generation Pipeline

Proto compilation via `buf v1.67.0`. Configuration in `buf.yaml` at the repository root.

Input: `proto/spidey/v1/*.proto`
Output: `proto/gen/go/spidey/v1/*.go`

Generated Go types live in the `gen/go` module (its own `go.mod`, depends on `google.golang.org/protobuf v1.36.3` only). All other Go modules import from `gen/go`.

Downstream: GraphQL schema (in service spec) and TypeScript types (in web spec) generate from these Go types, not directly from proto.

==== Scorer Request / Response

The Scorer interface is Go-only — there is no proto wire format. Backend-specific HTTP shapes (TEI `/rerank`, vLLM `/v1/chat/completions` with the zerank Yes-token logprob recipe) are encapsulated in their adapter packages and never surface above the adapter boundary.

[source,go]
----
// Caller's view — one query, N candidates, N aligned scores.
scores, err := scorer.Score(ctx,
    "Does that apply to the OAuth flow too?",
    []string{
        "The auth module retries failed token refreshes up to 3 times with exponential backoff.",
        "Unrelated discussion of the build pipeline.",
    },
)
// scores: [0.87, 0.04]  — higher = more relevant
----
