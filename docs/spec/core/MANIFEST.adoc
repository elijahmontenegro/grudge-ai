== Context

=== Identity

*Name:* {project-name} {module-name}

*Paradigm:* Provider-Agnostic Abstraction Library

The core library is the foundational Go package. It defines the abstraction interfaces and provider/embedder/scorer adapters. Proto truth types are defined in `proto/grudge/v1/` and generate to `proto/gen/go/grudge/v1/` -- core imports them, it does not own them. Core has no opinion on RRC, orchestration, UI, or deployment.

*Language:* {lang}

=== Scope

==== In Scope

- Proto truth types (three wire packages): Message, ContentBlock (Text, Thinking, ToolCall, ToolResult, Image, Attachment), Thread, Role, SelectionScope (grudge.thread.v1); LLMMessage, CompletionRequest/Response, StreamChunk, Usage, ToolDeclaration, ToolChoice (grudge.llm.v1); Edge, EdgeSource, SelectionResult, SelectedMessage, ExcludedMessage (grudge.rrc.v1)
- Completer interface: completion, streaming completion
- Embedder interface: dispatched embed (RoleQuery / RoleDocument)
- Scorer interface: query-against-candidates relevance scoring (cross-encoder pattern -- one query, N candidates, returns aligned scores)
- Provider role interfaces: CompleterProvider, EmbedderProvider, ScorerProvider (interface-segregated; each adapter implements only the roles it supports)
- Provider adapters: Ollama, Anthropic, OpenAI, Google AI, vLLM, any OpenAI-compatible endpoint
- Embedder adapters: TEI, OpenAI embeddings
- Scorer adapters: TEI `/rerank`, zerank/vLLM `/v1/chat/completions`
- Code generation pipeline: proto -> Go types via buf

==== Out of Scope

- RRC engine or algorithm (belongs to `spec/rrc`)
- Agent orchestration, agent loop, planning (belongs to `spec/service`)
- HTTP server, proxy, or service concerns (belongs to `spec/service`)
- UI, GraphQL schema, or presentation (belongs to `spec/web`)
- Conversation storage or persistence (belongs to `spec/service`)

== Implementation

=== Proto Truth Types

Defined in `proto/grudge/{thread,llm,rrc}/v1/` — one wire package per
stratum, generated into `proto/gen/go/grudge/{thread,llm,rrc}/v1/` as
`threadv1`/`llmv1`/`rrcv1`:

- **thread/v1/thread.proto** (leaf) -- Message, Role, ContentBlock (TextContent, ThinkingContent, ToolCallContent, ToolResultContent, ImageContent, AttachmentContent), Thread, SelectionScope
- **rrc/v1/rrc.proto** (imports thread) -- Edge, EdgeSource, SelectedMessage, ExcludedMessage, ExclusionReason, SelectionResult
- **llm/v1/llm.proto** (imports thread) -- LLMMessage, ToolDeclaration, ToolChoice, CompletionRequest, CompletionResponse, Usage, StreamChunk

Scorer is a Go interface only -- (query, []candidates) -> []float64 -- and has no proto wire form. Per-adapter HTTP shapes (TEI's `/rerank`, vLLM's `/v1/chat/completions` with the zerank Yes-token logprob recipe) live in each adapter's package.

Message is the corpus record (id, role, content blocks, position, thread_id, created_at). LLMMessage is the wire format (role, content blocks only). The service converts between them at the boundary. Thread is the organizational unit -- each thread is its own corpus with its own DAG and score cache. SelectionScope controls per-prompt scoping (thread-scoped by default, all-threads as opt-in).

CompletionRequest includes `provider_options` (`google.protobuf.Struct`) as an escape hatch for provider-specific parameters the abstraction does not model explicitly.

=== Go Interfaces

Provider-agnostic interfaces. The service consumes these without knowing the backend. The RRC engine defines its own consumer interface (Scorer) via Go structural typing -- any core adapter satisfies it.

The service configures two LLM roles: the **main model** (user's model for reasoning, tool use, responses) and the **small fast model** (internal utility for QUD extraction, annotations, autocomplete, tool rationale). Both use the same Completer interface with different provider/model configurations. The small fast model requires sub-second inference latency for autocomplete; QUD extraction tolerates multi-second latency. User selects a model matching these constraints during onboarding. Recommended models for the small fast role: sub-1B extraction-focused (Osmosis-Structure-0.6B, NuExtract-tiny, Qwen3.5-0.8B).

==== Embedder

[source,go]

type EmbedRole int

    RoleQuery EmbedRole = iota
    RoleDocument

type Embedder interface {
    Embed(ctx context.Context, role EmbedRole, texts []string) ([][]float32, error)

The role dispatch is for asymmetric instruction-tuned embedders (Qwen3-Embedding etc.) that need a query-side Instruct/Query prefix; symmetric models (bge-m3) ignore the role.

==== Scorer

[source,go]
----
type Scorer interface {
    Score(ctx context.Context, query string, candidates []string) ([]float64, error)
}
----

Higher score = more relevant. Output is aligned with input candidate order. Empty candidates returns an empty slice with no backend call.

=== Provider Role Interfaces

Adapters implement only the role interfaces they support. Splitting the god-interface (one method per role) means each adapter's capability surface is observable from its method set, not from a runtime probe. Callers type-assert on the role interface they need.

[source,go]
----
type CompleterProvider interface {
    Completer(model string) (Completer, error)
}

type EmbedderProvider interface {
    Embedder(model string) (Embedder, error)
}

type ScorerProvider interface {
    Scorer(model string) (Scorer, error)
}
----

A backend that exposes multiple roles (TEI: embeddings + reranking) implements multiple role interfaces. A pure-LLM provider implements only `CompleterProvider`. `ErrUnsupported` is returned by the registry lookup boundary when a caller requests a role the registered adapter doesn't satisfy.

=== Provider Adapters

Each adapter implements `Provider` for a specific backend. Configuration is adapter-specific.

==== Ollama
- Supports: Completer, Embedder
- Target API: Ollama HTTP API (as of v0.20.x)
- Endpoint: configurable HTTP base URL
- Models: whatever is pulled locally

==== Anthropic
- Supports: Completer
- Target API: Anthropic Messages API (`anthropic-version: 2023-06-01`)
- Endpoint: configurable base URL (default: `https://api.anthropic.com`)
- Auth: API key (`x-api-key` header)

==== OpenAI
- Supports: Completer, Embedder
- Target API: OpenAI `/v1/` (Chat Completions, Embeddings)
- Endpoint: configurable base URL (default: `https://api.openai.com`; any OpenAI-compatible endpoint)
- Auth: API key (`Authorization: Bearer` header)

==== Google AI
- Supports: Completer, Embedder
- Target API: Gemini API `v1` (stable)
- Endpoint: Gemini API
- Auth: API key

==== vLLM
- Supports: Completer
- Target API: OpenAI-compatible `/v1/` (as of vLLM 0.14.x)
- Endpoint: configurable base URL
- Auth: API key is a string config field. Empty string: adapter sends no `Authorization` header.

==== TEI
- Supports: Embedder, Scorer
- Target API: TEI HTTP endpoints (as of TEI 1.9.x)
- Endpoint: configurable HTTP base URL
- Embedder uses `/embed`, Scorer uses `/rerank`

==== zerank
- Supports: Scorer
- Target API: vLLM-served OpenAI-compatible `/v1/chat/completions`
- Endpoint: configurable HTTP base URL (default: `http://localhost:8000`)
- Production reranker — zeroentropy/zerank-1-small (1.7B Qwen3-based causal LM). Cross-encoder scoring via Yes-token logprob recipe: `sigmoid(logit / 5)`

=== Error Types

Sentinel errors. No retries -- the caller handles all error policy.

[source,go]
----
var (
    ErrUnsupported         = errors.New("capability not supported by provider")
    ErrAuth                = errors.New("authentication failed")
    ErrProviderUnavailable = errors.New("provider endpoint unreachable")
    ErrRateLimited         = errors.New("provider rate limit exceeded")
)
----

A type-assert on the wrong role interface fails — calling `core.NewProvider(...)` and asserting `(core.CompleterProvider)` on an adapter that doesn't expose completions returns `ErrUnsupported` at the assertion. Network failures return `ErrProviderUnavailable`. Invalid or expired API keys return `ErrAuth`. HTTP 429 from any provider returns `ErrRateLimited`.

Batch failure is all-or-nothing: any item fails → entire batch fails. `EmbedBatch` and `ClassifyBatch` do not return partial results.

=== HTTP Client

Internal shared HTTP client (`internal/httpc/client.go`). Used by all adapters.

[source,go]
----
type Client struct {
    http    *http.Client
    authFn  func(req *http.Request) // per-adapter auth (x-api-key, Bearer, etc.)
}

func New(timeout time.Duration, authFn func(*http.Request)) *Client
----

Default timeouts: 30s for non-streaming requests, 120s for streaming. Auth is a callback injected at construction — each adapter provides its own (Anthropic sets `x-api-key`, OpenAI sets `Authorization: Bearer`, Ollama/TEI set nothing).

=== Stream Contract

The adapter closes the channel when the stream ends or the context is cancelled. Channel is unbuffered. All `Completer`, `Embedder`, and `Scorer` implementations must be safe for concurrent use by multiple goroutines.

**`Complete` vs `Stream` method contract:** `Stream()` sets `stream=true` on the wire regardless of the proto field value. `Complete()` sets `stream=false`. The proto `bool stream` field exists for proto-level consumers; Go callers use method selection.

**Mid-stream errors:** `StreamChunk` carries an `optional string error` field. A chunk with `done=true` and `error` set indicates stream failure. Unexpected channel closure (no `done=true` received) is also an error — the caller treats it as a connection drop.

==== thread.proto

[source,protobuf]
----
syntax = "proto3";

package grudge.thread.v1;

option go_package = "github.com/elijahmontenegro/grudge/proto/gen/go/grudge/thread/v1;threadv1";

import "google/protobuf/timestamp.proto";

// A thread is a corpus — an ordered sequence of immutable messages.
// Each thread has its own DAG and score cache.
// Threads are the organizational unit. Selection is thread-scoped by default
// but can be widened to all threads per-prompt.

enum Role {
  ROLE_UNSPECIFIED = 0;
  ROLE_USER = 1;
  ROLE_ASSISTANT = 2;
  ROLE_SYSTEM = 3;
}

// Content block types. A message contains one or more of these.

message ContentBlock {
  oneof block {
    TextContent text = 1;
    ThinkingContent thinking = 2;
    ToolCallContent tool_call = 3;
    ToolResultContent tool_result = 4;
    ImageContent image = 5;
    AttachmentContent attachment = 6;
  }
}

message TextContent {
  string text = 1;
}

message ThinkingContent {
  string text = 1;
}

message ToolCallContent {
  string id = 1;
  string name = 2;
  string arguments = 3; // JSON-encoded arguments
}

message ToolResultContent {
  string tool_call_id = 1;
  string content = 2;
  bool is_error = 3;
}

message ImageContent {
  string media_type = 1;
  bytes data = 2;
}

// AttachmentContent: a file the user attached to the message, already
// imported into the thread's workspace. `path` is the sandbox-relative
// location the agent resolves via FileRead. `inlined_text` carries
// extracted UTF-8 text for text-like MIME types so RRC can chunk and
// score attachment content alongside prose; binary attachments leave
// it empty and are referenced by path only.
message AttachmentContent {
  string id = 1;            // UUID, also the subdirectory name under _attachments/
  string filename = 2;      // sanitized display name, also the basename on disk
  string mime_type = 3;     // sniffed from actual content at upload time
  int64 size_bytes = 4;
  string path = 5;          // sandbox-relative, e.g. "/workspace/_attachments/{id}/{filename}"
  string inlined_text = 6;  // populated for text/* MIME; capped at a reasonable size
}

// Corpus message. The persistent record in a thread.
// Has identity and position metadata beyond what the LLM sees.

message Message {
  string id = 1;
  Role role = 2;
  repeated ContentBlock content = 3;
  int64 position = 4;
  string thread_id = 5;
  google.protobuf.Timestamp created_at = 6;
  // Active-discourse identity. Messages produced within one outbound
  // model call (the triggering event plus the model/tool events it
  // spawns) share a turn_id, so the in-flight local discourse can be
  // recovered without falling back to fixed last-N recency. Empty on
  // messages stored before this field existed / outside a turn.
  string turn_id = 7;
}

message Thread {
  string id = 1;
  string name = 2;
  repeated string working_dirs = 3;  // Mounted directories. Mutable — add/remove over thread lifetime.
  bool sandboxed = 4;                // Whether tool execution runs in Docker Sandbox (default: true)
  google.protobuf.Timestamp created_at = 5;
  optional string parent_thread_id = 6;      // NULL for root threads, set for branches
  optional int64 branch_point_position = 7;  // Message position where this branch diverged
  optional google.protobuf.Timestamp archived_at = 8;  // NULL = active, set = archived
}

// Selection scope. Passed per-prompt to control where the RRC engine looks.

enum SelectionScope {
  SELECTION_SCOPE_UNSPECIFIED = 0;
  SELECTION_SCOPE_THREAD = 1;      // Default: select from this thread only
  SELECTION_SCOPE_ALL_THREADS = 2; // Widen: select from all threads
}
----

==== rrc.proto

[source,protobuf]
----
syntax = "proto3";

package grudge.rrc.v1;

option go_package = "github.com/elijahmontenegro/grudge/proto/gen/go/grudge/rrc/v1;rrcv1";

import "google/protobuf/timestamp.proto";
import "grudge/thread/v1/thread.proto";

// Prerequisite DAG edge. Produced by cross-encoder scoring or recorded
// as generation provenance.

enum EdgeSource {
  EDGE_SOURCE_UNSPECIFIED = 0;
  EDGE_SOURCE_CROSS_ENCODER = 1;
  // Recorded at generation time: "the turn at to_message_id was generated
  // from from_message_id." Not similarity-scored — it is a fact about what
  // fed the turn, legible even where semantic similarity is near zero. Its
  // `score` field carries the contribution weight (was the source
  // load-bearing for the turn, not merely present). Provenance edges are
  // the structural signal that lifts required-but-weakly-connected
  // prerequisites — roots above all — over calibrated acceptance.
  EDGE_SOURCE_PROVENANCE = 4;
}

message Edge {
  string from_message_id = 1;
  string to_message_id = 2;
  float score = 3;
  EdgeSource source = 4;
  float cross_encoder_score = 5;
  google.protobuf.Timestamp detected_at = 8;
  string from_thread_id = 9;  // Thread origin of the source message. Visible in citations when cross-thread.
  string to_thread_id = 10;
}

// Selection result. Returned by the RRC engine. Drives citations in the UI.

message SelectedMessage {
  string message_id = 1;
  float effective_score = 2;
  int32 hop_depth = 3;
  repeated Edge via_edges = 4;
  string thread_id = 5;       // Thread the selected message belongs to
  bool cross_thread = 6;      // True if selected from a different thread than the prompt
}

enum ExclusionReason {
  EXCLUSION_REASON_UNSPECIFIED = 0;
  EXCLUSION_REASON_BELOW_THRESHOLD = 1;
  EXCLUSION_REASON_TRANSITIVE_REDUCTION = 2;
  EXCLUSION_REASON_DEPTH_LIMIT = 3;
}

message ExcludedMessage {
  string message_id = 1;
  ExclusionReason reason = 2;
  float score = 3;
}

message SelectionResult {
  string event_id = 1;                // Unique ID for this RRC selection event
  grudge.thread.v1.SelectionScope scope = 2;           // Thread-scoped or all-threads
  string thread_id = 3;               // Thread where the prompt originated
  repeated SelectedMessage selected = 4;
  repeated ExcludedMessage excluded = 5;
  string local_context_fingerprint = 6;       // Exact bounded Local Context serialization
  repeated string local_context_message_ids = 7;
  string anchor_message_id = 8;       // Latest stored event receiving DAG edges
}

==== llm.proto

[source,protobuf]
----
syntax = "proto3";

package grudge.llm.v1;

option go_package = "github.com/elijahmontenegro/grudge/proto/gen/go/grudge/llm/v1;llmv1";

import "grudge/thread/v1/thread.proto";

// LLM interface types. Provider-agnostic completion.
//
// LLMMessage is the wire format — role + content blocks, no corpus metadata.
// The service converts between corpus Message and LLMMessage at the boundary.

message LLMMessage {
  grudge.thread.v1.Role role = 1;
  repeated grudge.thread.v1.ContentBlock content = 2;
}

// ToolDeclaration describes a tool the model can call.
message ToolDeclaration {
  string name = 1;
  string description = 2;
  // JSON Schema for the tool's parameters, as a JSON string.
  string parameters_json = 3;
}

// ToolChoiceMode controls whether and which tool the model is
// expected to invoke. Default (UNSPECIFIED) maps to AUTO. Each
// adapter translates to its provider's wire vocabulary.
enum ToolChoiceMode {
  TOOL_CHOICE_MODE_UNSPECIFIED = 0;
  TOOL_CHOICE_MODE_AUTO = 1;     // model chooses freely
  TOOL_CHOICE_MODE_NONE = 2;     // disallow tool calls
  TOOL_CHOICE_MODE_REQUIRED = 3; // require any tool call
  TOOL_CHOICE_MODE_NAMED = 4;    // require the named tool
}

// ToolChoice constrains the model's tool invocation. named_tool is
// only consulted when mode == TOOL_CHOICE_MODE_NAMED.
message ToolChoice {
  ToolChoiceMode mode = 1;
  string named_tool = 2;
}

message CompletionRequest {
  repeated LLMMessage messages = 1;
  string model = 2;
  optional int32 max_tokens = 3;
  optional float temperature = 4;
  optional float top_p = 5;
  repeated string stop = 6;
  bool stream = 7;
  // Tool declarations — functions the model can call.
  repeated ToolDeclaration tools = 9;
  // Tool-choice constraint. Optional — unset means model decides.
  ToolChoice tool_choice = 10;
}

message CompletionResponse {
  string id = 1;
  LLMMessage message = 2;
  Usage usage = 3;
  string model = 4;
  // Why generation stopped. Provider-specific strings, normalized
  // by the adapter to: "stop", "length", "tool_calls",
  // "content_filter", or empty.
  string finish_reason = 5;
}

message Usage {
  int32 prompt_tokens = 1;
  int32 completion_tokens = 2;
}

// Streaming. Each chunk carries a content block delta.

message StreamChunk {
  oneof delta {
    grudge.thread.v1.TextContent text = 1;
    grudge.thread.v1.ThinkingContent thinking = 2;
    grudge.thread.v1.ToolCallContent tool_call = 3;
    grudge.thread.v1.ToolResultContent tool_result = 7;
  }
  bool done = 4;
  optional Usage usage = 5;
  optional string error = 6;  // Set on stream failure (done=true + error = failure)
  // Provider-specific finish reason on the final chunk. Empty when
  // generation has not stopped (intermediate chunks) or the
  // provider didn't supply one.
  string finish_reason = 8;
  // Choice index for providers that emit multiple parallel
  // completions (OpenAI's `n` parameter). Default 0 — single-choice
  // path.
  int32 choice_index = 9;
}

==== Scorer Request / Response

The Scorer interface is Go-only — there is no proto wire format. Backend-specific HTTP shapes (TEI `/rerank`, vLLM `/v1/chat/completions` with the zerank Yes-token logprob recipe) are encapsulated in their adapter packages and never surface above the adapter boundary.

[source,go]
----
// Caller's view — one query, N candidates, N aligned scores.
scores, err := scorer.Score(ctx,
    "Does that apply to the OAuth flow too?",
    []string{
        "The auth module retries failed token refreshes up to 3 times with exponential backoff.",
        "Unrelated discussion of the build pipeline.",
    },
)
// scores: [0.87, 0.04]  — higher = more relevant
----
